# Limitations-resolution matrix (v1.1 follow-up, 2026-10-12)

Scope set by the owner: private learning and business development; global market; deeper EU/Latvia treatment only where location affects operating a global agent business. Prior version preserved in `archive/v1.0/` and git tag `v1.0` (commit 783cee5).

Outcome categories describe **evidence gaps**, not project completion:
- **RESOLVED:** the exact claim was verified against the primary source.
- **PARTIALLY RESOLVED:** materially improved, but a residual gap remains.
- **UNRESOLVED AFTER DOCUMENTED SEARCH:** the search scope is documented and nothing adequate was found.
- **REMOVED OR REPLACED:** the claim was dropped or substituted.

## 3. Search scope for unresolved items

- **Agent ban rates (C).** Searched: platform transparency pages (Anthropic, OpenAI), DSA transparency materials, community forums (OpenAI, Google AI Developers), Cloudflare blog and Radar pages, security and SEO blogs, and academic search terms ("agent ban rate", "automation enforcement statistics"). Not searched: paid datasets, and the EU DSA Transparency Database (statement-of-reasons API). That database is a candidate for future work for platforms that report there. Missing: an agent-specific numerator plus an exposure denominator.
- **Scheduled and continuous agent timing (B).** Searched: provider economic and usage reports, Cloudflare Radar, OpenRouter, GitHub-based datasets, scheduler documentation. Missing: provider telemetry split by trigger type. What could resolve it: a provider publishing hour-of-week distributions for scheduled vs human-triggered runs, or the operator's own logs (§10.4).
- **Global autonomous purchase value (D).** Searched: Visa, Mastercard and Stripe releases, Visa earnings coverage, onchain analytics (Visa/Artemis, TRM, Coinbase claims), retail analytics (Adobe), consumer surveys. Missing: card-network disclosure of agent-token transaction volume and value; merchant-side signed-agent order data.
